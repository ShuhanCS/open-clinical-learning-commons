# APP-4 Module 02 data specification

## Inherited public evidence

The learner workspace includes the 29 immutable Module 01 control, profile, and complete NHANES source files under `inherited/module01/`. Those hashes preserve the accepted source-feasibility chain of custody. NHANES remains historical public survey evidence and is not used to manufacture local workflow truth.

## Complete synthetic FHIR release

`data/synthetic-release/` contains the complete generated output for the pinned configuration:

- release: `CGH-GIM-01-SYNTHETIC-2026-08-31-v1`;
- generator: Synthea 4.0.0;
- population: 1,000 synthetic Massachusetts adults, ages 18 to 89, alive at the fixed reference date;
- FHIR: R4, with the US Core 7.0.0 exporter setting;
- history: five years;
- files: 24 NDJSON resources plus one FHIR Bulk Data Parameters manifest;
- resources: 811,803 rows;
- size: 1,549,494,665 UTF-8 bytes before compression and 100,178,478 committed gzip bytes;
- parse failures: zero; and
- duplicate resource IDs within file: 11,109.

The duplicate IDs occur in repeated organization and provider resources. They are preserved as upstream output and must be resolved by an explicit normalization policy before any analytic join. The module does not silently deduplicate them.

The Synthea Windows output is read as Windows-1252 and rewritten as canonical UTF-8 JSON with deterministic gzip timestamps. This changes byte encoding and whitespace, not resource values.

Both the Synthea reference date and end date are fixed at `20260831`. Two clean generations produce the exact same 25-file manifest.

## Commons teaching fixtures

`data/commons/` contains:

- `patient-linkage.csv`: 16 case IDs linked to the first 16 patients in the pinned synthetic release;
- `rule-test-cases.csv`: normal, boundary, missing, stale, inconsistent, duplicate, delayed, terminology-mismatch, version-mismatch, suppression, unit-mismatch, context-mismatch, silent-failure, and missing-score cases; and
- `logic-config.json`: the fictional service, hook, hook version, candidate lookback, mock threshold, and authority limits.

The fixture score is supplied directly. It is not generated by a model. The mock threshold is arbitrary and tests only `less than` versus `at or above` branch behavior.

## Event-time rule

Only information available at or before `2026-08-31T15:00:00Z` may enter a fixture evaluation. A delayed value cannot be treated as missing at random or silently moved backward in time. Effective time, recorded time, and availability time remain distinct.

## Data classes and claims

All FHIR and Commons rows are synthetic teaching data. No real patient, employment, local EHR, or protected data may enter the module. Passing the fixtures establishes deterministic code behavior only. It does not establish real prevalence, discrimination, calibration, net benefit, clinical correctness, local workflow fit, safety, fairness, or deployment readiness.
