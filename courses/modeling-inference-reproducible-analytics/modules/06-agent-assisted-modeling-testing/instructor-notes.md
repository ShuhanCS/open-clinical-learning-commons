# Instructor notes

Teach the failure fixtures before discussing agent quality. A system that produces fluent test code is useful only when the learner can state what the test protects and prove it fails for the intended reason.

Suggested order: classify data; bound the prompt; inspect immutable artifacts; run accepted tests; predict each fixture's code; run failures; independently recalculate confusion and forecast errors; adjudicate four claims; complete trace and sign-off.

Probe these misconceptions: more tests mean better assurance; any rejection counts; repeating a prompt is independent; synthetic data remove all governance duties; a high p-value proves a model; a passing technical suite approves deployment; and an agent can sign as reviewer.

Checkpoint 2 remains blocked until actual learner and reviewer sign-off is present, even though the runnable reference passes technical validation.
