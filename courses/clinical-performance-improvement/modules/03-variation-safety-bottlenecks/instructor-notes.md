# Instructor notes

Lead with the distinction between a signal and a diagnosis. The chart tells the learner where review is warranted. The stage, control, queue, throughput, staffing, balancing, and recovery evidence together determine whether a bounded process statement is supportable.

Do not hide the baseline run signal. It is the best teaching feature in this module. Weeks 4 through 11 form an XmR high run, so the first 24 weeks are not a verified stable control phase. Learners may calculate the provisional limits, but they must not call them live operational thresholds.

The reference diagnosis is deliberately narrower than a staffing explanation. Roomed-to-clinician time rises from 49 to 66 minutes in the target evening window and returns to 49 minutes in recovery. Clinician hours per arrival are not lower. That combination localizes the stage and weakens a simple low-hours story, but it does not explain the generated mechanism in real operational terms.

The safety chart has no exact Poisson limit breach but does have a low run. Generated truth shows undercapture by class, not a temporal improvement. Require learners to retain the signal as a review prompt and reject any claim that safety improved.

The target-window standard group has support, while language and mobility groups do not. One supported reference group cannot make a cross-group comparison valid.

The base-R script is supplied for learners to read and run because the course expects interpretation of statistical process control code. R is not installed in the construction environment, so Python is the deterministic release authority. Before alpha, an independent R reviewer must run the script and record the result.
