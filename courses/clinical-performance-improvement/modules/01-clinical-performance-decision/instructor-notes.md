# APP-3 Module 01 instructor notes

## Teaching purpose

The common mistake in performance-improvement work is to start with a dashboard, a suspected bottleneck, or a staffing answer. Keep this module earlier in the reasoning chain. Learners should leave with a bounded service decision and evidence contract, not a diagnosis.

## Suggested sequence

1. Ask learners what exactly moves through the service and when its clock starts and stops.
2. Compare public reporting grain with the future synthetic event grain.
3. Inspect unavailable CMS values and HHS sentinels as evidence about feasibility.
4. Sort proposed measures into outcome, process, balancing, safety, capacity, access, and equity roles.
5. Make each learner name who can act, who can stop the work, and who bears burden.
6. Challenge every statement that sounds like a current local finding.
7. End with the progression gate and owned conditions.

## Reference disposition

The reference package reaches `continue with conditions`. It permits Module 02 to build local measure definitions from the fictional event model. It does not authorize operational diagnosis, staffing change, clinical action, public hospital comparison, or implementation.

## Instructor interventions

- If a learner says a public facility resembles `CGH-ED-01`, require removal of the linkage.
- If a learner treats `Not Available` or `-999999` as zero, stop the analysis and repair the source interpretation.
- If a learner proposes staffing, return to the unit-of-flow and evidence-needed records.
- If a learner starts calculating rates, ask which Module 02 measure specification would make the rate defensible.
- If a learner ranks hospitals, require a claim-boundary correction.
