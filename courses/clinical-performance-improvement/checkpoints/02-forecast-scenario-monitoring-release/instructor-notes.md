# Instructor notes

## Teaching purpose

The Week 6 checkpoint teaches cumulative evidence discipline. Learners should not improve the story by dropping an unfavorable scenario, filling an unavailable measure, or accepting a promising ML challenger that failed one declared rule.

## Facilitation

1. Begin with the 0, 25, 0 point map.
2. Ask learners to trace one forecast row from Module 04 through Module 06.
3. Require the word `none` before discussing scenario feasibility.
4. Assign one group to forecast and capacity limits, one to scenario failures, one to monitoring and access, and one to ML comparability.
5. Recombine the groups for the 14-question defense.
6. Ask what Joe Joseph, MD, should hear first in Module 07: the decision, the strongest evidence, the failure that could change interpretation, and the authority boundary.

## Expected decision

The reference continues with conditions. The evidence chain is complete, but no scenario qualified, the transparent forecast remains accepted, three measures remain prospectively unavailable, one ML replacement rule failed, and no implementation authority exists.

## Do not repair inside the checkpoint

If a learner disputes a fold, model, scenario, threshold, measure, or disposition, record the issue and return it to the owning module. A checkpoint is a frozen review package, not a new analysis release.
